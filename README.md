# ForestFile

CMSSW HTCondor batch workflows for oxygen (pO) heavy-ion Monte Carlo production and HiForest ntuple making.

Two independent stages, run in **separate folders**:

| Folder | What it does | Output |
|---|---|---|
| [`runHeavyIons/`](runHeavyIons) | **Generates MC events** and runs them through GEN → SIM → DIGI-RAW → RECO → **MiniAOD** | MiniAOD files |
| [`runHIForest/`](runHIForest) | Runs the [CmsHI `forest`](https://github.com/CmsHI/cmssw) package over a MiniAOD (or AOD) file list | **HiForest** ntuples (`.root` analysis trees) |

`runHeavyIons` is Monte Carlo only — it *generates* collisions, so there is no equivalent for real collision data.
`runHIForest` is the stage that also applies to **real data**: point it at an official data MiniAOD/AOD dataset instead of a locally-produced one.

> **Note for running on data, not MC:** the only forest config currently in this repo is
> [`runHIForest/pythiafragments/forest_CMSSWConfig_Run3_OXY_MC_miniAOD.py`](runHIForest/pythiafragments/forest_CMSSWConfig_Run3_OXY_MC_miniAOD.py),
> which is set up for MC (MC GlobalTag, MC-only forest producers). To run over real data you need a
> **data-flavored forest config** (correct data GlobalTag, drop the MC-truth producers) — ask the CmsHI
> `forest` package for the data variant matching your run era, or adapt this one. This hasn't been added yet.

## How each stage works

### `runHeavyIons` (MC generation → MiniAOD)
1. `HI_buildInputs.sh <year> [merge]` — picks a generator fragment from `pythiafragments/` (Pythia+Angantyr, AMPT, EPOS, HIJING, HYDJET, ...), builds a `submit/` area + `inputs.sh` config, and tars it into `work<year>_<process>/submit.tgz`.
2. `submitHI.py <workdir> <njobs>` — submits `<njobs>` HTCondor jobs from that work directory.
3. On the worker node, `exec2025HI.sh` untars the payload and runs `submit/runEventGeneration_special.sh` (sets up CMSSW, runs the GEN→SIM→DIGI-RAW→RECO→MiniAOD chain via `cmsRun`).

### `runHIForest` (MiniAOD/AOD → HiForest ntuple)
1. `HIForest_buildInputs.sh <year> [merge]` — takes a file list from `inputs/` (e.g. `official_pO_MC_part_XX.txt` or your own MiniAOD/data list), copies in `pythiafragments/forest_CMSSWConfig_Run3_OXY_MC_miniAOD.py`, and packages `work<year>_<name>/submit.tgz`.
2. `submitHI.py <workdir>` (or the convenience wrappers `bJobs.sh` / `bJobsOFFICIAL_MC.sh`) — submits the HTCondor job(s).
3. On the worker node, `exec2025HI.sh` runs `submit/runHiForest_2025.sh`, which sets up CMSSW, checks out `CmsHI:forest_CMSSW_15_0_X`, runs `cmsRun forest_CMSSWConfig_Run3_OXY_MC_miniAOD.py`, and `xrdcp`'s the resulting HiForest `.root` file to EOS.

## Before you run this (things you must edit)

These scripts have **hard-coded paths and account names** from the original author and won't run for anyone else as-is:

- `submitHI.py` in both folders: `logpath = '/afs/cern.ch/user/.../Logs...'`, `x509userproxy`, `+AccountingGroup = "analysis.<username>"` — change to your own username/proxy path.
- `runHIForest/bJobs.sh`, `bJobs.sh`, `bJobsOFFICIAL_MC.sh`: hard-coded `cd /afs/cern.ch/user/m/mtayyera/work/runHIForest` — change to your own checkout path.
- `runHIForest/submit/runHiForest_2025.sh`: the final `xrdcp` destination (`/eos/cms/store/group/phys_heavyions/mtayyera/...`) — change to your own EOS area.
- You need a valid grid proxy (`voms-proxy-init`) saved at the path referenced by `x509userproxy` before submitting.

## What is intentionally *not* in this repo

Batch logs, per-submission `work*/` scratch/output directories (generated `submit.tgz`, compiled CMSSW build trees, and `.root` outputs), and editor swap files are excluded — they're regenerated by the scripts above and would bloat the repo. See `.gitignore`.
